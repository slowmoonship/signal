# DESIGN.md —— Signal 的视觉规范

Phase 3 落地，Phase 4.6 重排首页时更新，V0.1 补上市场状态卡片底色。`CLAUDE.md §视觉红线` 是约束的**来源**，
本文件是它在代码里的**落地形态**：每个 token 定义在哪、组件怎么用、哪些做法被明确禁止、
以及每条禁令由什么来守。

改视觉之前先读本文件；改完之后跑 `npm run test`——视觉红线里的每一条都有对应的守卫测试。

---

## 1. 三条红线与它们的理由

### 1.1 只用灰阶

不用彩色表达涨跌，方向靠 `+` / `−` 符号。

除了"极简"，真正的原因是**语义方向因指标而异**：矿工收入涨是好事，费率涨不是，
交易所净流出涨可能是卖压也可能是合规转移。用红绿去标，等于替读者下了一个它未必成立的判断。
灰阶没有这个问题：符号只陈述方向，不表态。

例外只有四处，每一处都只承担**一个**职责，且都有测试守着：
分类底色（§1.4）、状态色（§1.6）、高亮绿（§1.5）、市场状态卡片底色（§1.7）。

实体标签（矿池、交易所、巨鲸）同理——它们本来就是启发式标注（数据红线 6），
染色会让读者误以为标签本身是权威事实。

**唯一的例外是分类底色**（§1.4），且它被 CLAUDE.md 明文授权：它只承担"分组"这一个职责，
不参与涨跌、告警、链接的任何着色。

### 1.2 不用阴影、胶囊圆角、彩色按钮、渐变

层级靠**字重与间距**，不靠装饰。这条不是审美偏好：
它同时消灭了"元素该有多突出"这个需要逐处判断的问题，
排版层级因此是可预测的——`<h1>` 一律 `text-2xl font-semibold`，
小节标题一律 `text-xs font-medium uppercase tracking-widest`，没有例外。

### 1.3 元信息用等宽字体

时间、来源、数值单位、数值本身一律 `font-mono`，并开 `font-feature-settings: 'tnum' 1`。
指标数值要在首页 19 行之间横向对齐比较，字宽不等就谈不上比较。

### 1.4 分类底色：全站唯一允许的彩色

首页表格按分类分组，同一组的行共用一个极浅的底色。灰阶也能分组（画横线），
但 11 行连续横线在视觉上是一片，读者得逐行数才知道哪些行属于同一组——
分组信息没有被编码进去。底色把它编码进去了。

三条硬约束，全部由 `apps/web/test/theme.test.ts` 守住：

1. **色值只写在 `globals.css` 的 `:root` / 暗色媒体查询里**。
   组件只出现 `bg-cat-market` 这类语义工具类；真实色值由
   `apps/web/src/lib/categories.ts` 的 `CATEGORY_TINT` 独家持有，
   它的类型是 `Record<MetricCategory, string>`（不是索引签名）：
   新增分类时这个文件编译不过，而不是静默渲染成"没有底色的组"。
2. **低饱和**（HSL 饱和度 ≤ 40%），明暗两态都只做背景填充，**不许改文字颜色**。
3. **只做背景**。涨跌、告警、链接一律不染色。

饱和度 40% 的上限意味着这六个颜色在白底上几乎读成灰——这是刻意的。
一旦底色开始传递"红 = 危险 / 绿 = 安全"，它就在替读者下判断，
而"涨"对不同指标含义相反（矿工收入涨是好，费率涨不是），染色等于替读者做决定。
**底色不该有态度。**

分类名与色相的对应是任意的，不要试图从中读出语义：灰色不代表中性，暖色不代表危险。

**行悬停用半透明的 ink 叠加（`hover:bg-ink/[0.03]`），不用不透明底色。**
行背景会画在行组背景之上——不透明的悬停底色会把整组的分类底色盖掉，
鼠标扫过一组时同组行先后"掉了色"，分组边界在读者眼前闪一下就没了。
半透明叠加保留色相。

### 1.5 高亮绿：走势图上的彩色强调，只标一个区间

首页十年价格走势图上，**最长定投等待期的那一段**用一条 `--highlight` 绿标出，
起点日到首次达标日。走势图上除此之外全是灰阶。

全站另有一处绿色——市场状态卡片的"条件明确改善"底色（§1.7）。
它是**另一个 token**（`--market-improving`）、另一个语义、另一个位置：
`--highlight` 标一段**区间**，"这段最难受"；`--market-improving` 标一个**结论**，
"这一轮条件在变好"。两者不许共用同一个绿色——共用之后，
读者会把"这段最难受"读成"现在适合买"，绿色就又变成了"好"。

同一段区间同时画成一条**贯穿整个绘图区高度的浅绿色背景带**（`fill-highlight`，透明度 0.14）。
只把价格线染绿的话，那一段在十年曲线里只是"细线变粗"，
读者很难一眼看出它**横跨了多长一段时间**——而"多长"正是这条信息要说的。
背景带把时间跨度直接框出来，横轴上有实感；绿色曲线画在带子**上层**，不被盖住。
带子的左右边界由 `worstCase` 的两个时间戳换算而来，
**不写死任何日期或像素坐标**：数据一变，区间跟着变。

它和分类底色的区别必须讲清楚，否则这条口子会慢慢长成"绿色 = 好"：

- 分类底色**不做背景以外的任何事**；高亮绿**只标一个具体区间**，别的什么都不做。
- 这段区间是回测算出来的**事实**（"历史上最久的一次，要等 340 天"），
  不是对"该买还是该卖"的判断。它标的是"这段最难受"，不是"这段最值得买"。
- 因此文案里**不许**出现"绿色 = 适合定投 / 绿色 = 底部"这类说法，
  `theme.test.ts` 与 `copy.test.ts` 都会因此失败。

走势线本身是灰阶（`--ink`），网格线是 `--rule`，没有渐变、没有填充面积。

### 1.6 状态色：全站唯一允许染色的数据含义

首页表格的**当前状态**列是一个低饱和药丸，`--status-hot` / `--status-flat` / `--status-cold` / `--status-void` 四档。

它与前两者的分工必须讲清楚，三者各管一件事，互不越界：

| | 颜色在说什么 | 作用范围 | 判错的后果 |
|---|---|---|---|
| 分类底色 | 这一行属于哪一组 | 整行背景 | 分组边界读不出来 |
| **状态色** | 这个数**相对它自己近一年处在什么位置** | 三个字的胶囊 | 把"位置"读成"评级" |
| 高亮绿 | 最长等待期是**哪一段区间** | 走势图的一条线 | 把"事实"读成"建议" |
| 市场状态卡片底色 | **这一轮条件在变好还是变差** | 一张卡片的背景 | 把"改善"读成"该买" |

三条硬约束：

1. **色值只写在 `globals.css`**，组件只用 `bg-status-hot` 这类语义类（与 `--cat-*` 同款约束）。
2. **底色饱和度 ≤ 40%**，与分类底色同一个上限。红蓝只要在明度上分得开，
   不需要靠饱和度喊；底色越"响"，读者越容易把它读成告警而不是位置提示。
   （文字色 `-ink` 不受此限——它负责对比度，不负责安静。）
3. **不用绿色。** 绿色已经是"最长等待期"（§1.5）与"条件改善"（§1.7），
   一旦绿色也表示"偏强"，"绿色 = 好"立刻就长回来了。
   冷暖用**红 / 蓝**而不是红 / 绿，原因相同。

**"hot" 不等于"该买"。** `hot` 的全部含义是"这个数比过去 80% 的日子高"。
交易所净流入是 hot，矿工收入上升也是 hot——两者对读者的意义完全不同，
所以这个色档刻意不表达好坏。判不出来时是 `--status-void` 的"缺数据"，
并把原因挂在 `title` 上；**任何情况下都不许为了让表格整齐而填"中性"**
（CLAUDE.md §数据质量红线 8）。

`theme.test.ts` 守着 1–3，`status.test.ts` 守着"该出现"与"不该出现"的词。

### 1.7 市场状态卡片底色：条件在变好还是变差

首页左栏那张独立的「市场状态」卡片用**极浅的底色**表达方向：
条件明确改善 = 浅绿 `--market-improving`，明确恶化 = 浅红 `--market-deteriorating`，
中性 / 分化 / 信号冲突 / 判不了 = `--market-neutral`（= 卡片原来的背景）。

底色只是**辅助**：那句话必须留着，颜色替读者省掉的是读那句话之前的���一眼。

四条硬约束：

1. **颜色来自规则的结构化结果，不来自文案。**
   `packages/metrics/src/market/` 算出 `MarketRead.tone`
   （`improving` / `deteriorating` / `neutral`），页面只把 tone 映射成类名。
   **不许**去匹配句子里有没有"上涨 / 下跌"——同一个词在不同规则里含义相反，
   照着文案染色必然染错。
2. **"当前偏强"不等于"正在改善"。**
   只有断言了**条件变化**、且判据里带时间序列比较（变化量、方向反转、
   相对自身历史的变化幅度）的规则才允许染色。
   "价格仍在近一年高位"是**位置**，保持中性。
   这条写成了测试：任何用到水平分位（`levelPercentile`）特征的规则，tone 必须是 `neutral`。
3. **证据不足就保持中性。** 分化、信号冲突、常态兜底，以及"判不了"一律中性；
   不许为了让卡片好看而强行染色。
4. **只染这一张卡片。** 右栏指标表一个都不染——每行都染，读者会以为整张表
   在表达同一个判断。底色只做背景填充，文字颜色不变。

色值只写在 `globals.css` 的 `:root` 与暗色媒体查询里（明暗各一份，
中性档 = `var(--surface)`），走 `@theme inline` 映射成 `bg-market-*`。

底色饱和度上限比分类底色、状态色宽一档（≤50%，而不是 ≤40%），理由是**职责不同**：
那两处的颜色是背景，职责是"别被读成态度"；这里的颜色**本身就是结论**——
读者要的是一眼看出方向，底色太淡就等于没做。
但明度仍然压得很浅（浅色态 ≥92%），仍然是**极浅的底**，不是色块。

## 2. Token

全部定义在 `apps/web/src/app/globals.css`。

### 2.1 颜色：为什么是 `:root` + `@media` + `@theme inline` 三段

```
:root                       真实取值（明）
@media (prefers-color-scheme: dark) { :root { … } }    真实取值（暗）
@theme inline { --color-ink: var(--ink); … }           语义名 → 工具类
```

Tailwind v4 的 `@theme` **只在构建期求值**。把暗色值也写进 `@theme`
（哪怕嵌套在媒体查询里）产出的仍是一组被后者覆盖的 `:root` 常量，
而 `text-ink` 早已在构建期被编译成固定的浅色十六进制——**暗色主题看着配了，实际永远不生效**。
`@theme inline` 让工具类直接引用 `var(--ink)`，值在运行时才解析，媒体查询的覆盖才起作用。

这个坑在 Phase 3 的第一版就踩过：`grep` 产物 CSS 时发现暗色块里只有 `dark:` 工具类、
`--color-ink` 全局只出现一次。`apps/web/test/theme.test.ts` 现在有一条断言专门守它。

### 2.2 语义色

| token | 明 | 暗 | 用在哪 |
|---|---|---|---|
| `--surface` | `#ffffff` | `#09090b` | 页面底色 |
| `--surface-sunken` | `#fafafa` | `#18181b` | 凹陷面（无底色区域的分隔底） |
| `--ink` | `#18181b` | `#e4e4e7` | 标题、指标名、**数据线** |
| `--ink-muted` | `#52525b` | `#a1a1aa` | 说明正文、来源名、页脚 |
| `--ink-subtle` | `#a1a1aa` | `#71717a` | 时间戳、刻度、次要标签 |
| `--rule` | `#e4e4e7` | `#27272a` | 分隔线、图表网格线 |
| `--rule-strong` | `#d4d4d8` | `#3f3f46` | 告警框边框 |
| `--cat-*` | `hsl(… ≤40% 96%)` | `hsl(… ≤40% 13–14%)` | **仅**首页表格的分组底色（§1.4） |
| `--highlight` | `hsl(150 62% 32%)` | `hsl(150 58% 55%)` | **仅**首页价格走势图上最长定投等待期的那一段区间（§1.5） |
| `--status-{hot,flat,cold,void}` | `hsl(… ≤40% 95–96%)` | `hsl(… ≤40% 17–19%)` | **仅**首页表格的状态胶囊底色（§1.6） |
| `--status-*-ink` | `hsl(… 34–46%)` | `hsl(… 58–74%)` | 状态胶囊的文字 |
| `--market-improving` | `hsl(150 48% 92.5%)` | `hsl(150 45% 16%)` | **仅**市场状态卡片"条件明确改善"的底色（§1.7） |
| `--market-deteriorating` | `hsl(4 50% 94%)` | `hsl(4 50% 17%)` | **仅**市场状态卡片"条件明确恶化"的底色（§1.7） |
| `--market-neutral` | `var(--surface)` | `var(--surface)` | 市场状态卡片的中性底色（= 卡片原背景） |

`--cat-*` 有六个：`market` / `onchain` / `exchange` / `fees` / `mining` / `valuation`。
它们与 `--surface` 一样走 `:root` + 媒体查询 + `@theme inline` 三段结构（§2.1），
所以暗色态同样真正生效。

**组件里不出现 `zinc-300` / `zinc-700` 这类具体色阶。**
理由是可维护性：18 个指标 × 2 主题如果各自挑色阶，
调一次对比度要改几十处，而且没人说得清哪一处的 zinc-500 是"次级"还是随手写的。
语义名把"这一层墨色代表什么"固化下来，取值只在 `globals.css` 一处。

图表里数据线用 `--ink`、网格线用 `--rule`，是同一套层级关系——
明暗两态只切换取值，不切换层级。

### 2.3 字体

`apps/web/src/lib/fonts.ts`，`next/font/google` 注入两个 CSS 变量：

- **Inter** —— 拉丁字母与数字。指标数值、时间戳、来源都是拉丁/数字，
  由它承载保证 `tabular-nums` 下数字等宽对齐。
- **Noto Sans SC** —— 中文。中文与西文混排时字面高度和字重必须显式配对，
  只声明其中一个会让另一类字符掉回系统字体，字重对不上。

只请求 400 / 500 / 600 三个字重：全站只用到 `font-medium`、`font-semibold` 与正文默认的 400。

`--font-sans` 的末尾保留完整系统字体栈（`ui-sans-serif` … `PingFang SC` …）。
web font 没加载成功时退回本机 CJK 字体，而不是出现空白字形。

**`--font-mono` 仍是纯系统栈**（`ui-monospace, 'SF Mono', Menlo, Consolas`）。
等宽字体不打包：元信息全是数字与短标签，系统等宽字体足够，
而再打一套 Inter Mono 只会让 4.8 MB 的字体目录更大。

> 构建成本：Noto Sans SC 被 Google 按字频切成约 101 个 chunk × 3 字重 = 305 条 `@font-face`，
> 产物 4.8 MB。浏览器只下载页面实际用到的 chunk（实测覆盖 888 个汉字码位），
> 但**每次 CI 构建都要重新下载这 4.8 MB**。若日后 CI 构建时间成为瓶颈，
> 第一个该考虑的就是把 Noto 换成自托管子集，而不是砍中文字体。

## 3. 主题切换：没有开关

明暗跟随 `prefers-color-scheme`，**不提供手动切换**。

一旦允许手动切换，就必须在第一帧之前知道用户选了什么——那意味着一段内联脚本。
对一个日更快照的静态站来说，这段脚本要防的闪烁本身就不存在：
`prefers-color-scheme` 在第一帧就已确定。

如果日后加上开关，`globals.css` 的三段结构是为此准备的：
变量都在 `:root` 上，手动切换只需要覆盖同一批变量，不需要动任何组件。

## 4. 排版层级

字重只有三档：`font-normal`（默认 400）、`font-medium`（500）、`font-semibold`（600）。
全站没有第三档以上，也不用字号做层级跳跃。

| 角色 | class |
|---|---|
| **品牌字标（页头）** | `text-2xl sm:text-[28px] font-semibold tracking-tight` |
| 站点说明（页头下的副标题） | `text-base sm:text-lg text-ink-muted` |
| 页面标题 / 指标名 | `text-2xl font-semibold tracking-tight` |
| **头条大指标（首页 hero）** | `text-5xl sm:text-6xl font-mono tabular-nums` |
| 指标数值（详情页） | `text-2xl sm:text-3xl font-mono tabular-nums` |
| 数值（首页表内） | `text-sm font-mono tabular-nums` |
| 小节标题 | `text-xs font-medium uppercase tracking-widest text-ink-subtle` |
| 说明正文 | `text-[15px] leading-relaxed text-ink-muted` |
| 元信息 | `text-xs font-mono text-ink-subtle` |

中文正文用 `text-[15px]` 而不是 `text-base`：16px 下中文行高偏松，
15px + `leading-relaxed` 在 640px 宽度上每行能多容纳几个字而不显拥挤。

**字标与说明性标题的字号关系是反的，而且必须反着。**
字标（"Signal"）放大到 26–30px，说明性标题（"比特币市场与链上指标目录"）
缩到 16–18px：品牌是这一站的名字，说明只是注解。
早先的排版把说明做成了 `text-2xl` 的 `<h1>`、字标只有 `text-sm`，
于是说明性文字抢走了整页的视觉焦点——读者第一眼看到的是一句自我介绍，
而不是站名。页头到正文的距离也因此收紧（`pt-6 pb-3` + 内容区 `mt-5`）。

**头条大指标是全站唯一的超大字号**，它不遵守"不用字号做层级跳跃"——
它就是那个跳跃本身：一眼扫过去，页面上只有一个数字是"今天最该知道"的。

## 5. 首页布局

桌面两栏，窄屏上下堆叠。**不是卡片墙**（ADR-005 的"极简"约束的是装饰，不是信息密度）。

```
┌──────────────────────────┬────────────────────────────────────────────────┐
│ 定投赚 5%，最长等多久？   │ 分类 │ 指标 │ 当前值 │ 7日变化 │ 状态 │ 判定依据 │
│ 340 天                   │ ─────┼──────┼────────┼────────┼──────┼────────  │
│ 一句话解释（两句）         │ 市场 │ 价格 │ …     │ …      │ 中性 │ 分位 P66 │

│ └──────────────────────┘ │ ─────┼──────┼────────┼────────┼──────┼────────  │

```

左栏是**一个**头条大数字、四个补充数字、一条十年价格走势图、一句话市场状态；
右栏是 17 个指标分六组，**六列**：分类 / 指标 / 当前值 / 7 日变化 / 当前状态 / 判定依据。

**左栏那张「市场状态」卡片带底色**：条件明确改善是极浅的绿，明确恶化是极浅的红，
分化 / 冲突 / 判不了保持卡片原来的背景（§1.7）。
颜色由命中规则的结构化结果决定，**不看那句话里有没有"上涨"**；
底色只是辅助，那句话一个字都不能少。右栏的指标表一格都不染。

左栏在宽屏是 `sticky` 的：表格滚过去之后，"最久要等多少天"这句话应该留在视线里——
它是读者来这个站点的首要理由。

**左栏要短。** 头条只回答"最坏要等多久"，答案是 340 天；剩下四个数字
（已达标起点 / 尚未达标 / 中位 / P90）把**这一个最大值还原成一个分布**——
只给 340 天，读者会以为那就是常态。解释文压到两句：完整口径在详情页里，
左栏要的是"一眼看懂"，不是"一次读完论文"。

> 标题写"定投赚 5%，最长等多久？"，下面紧跟一句限定"历史已达标样本中的最长等待"。
> 两个都要：标题负责让人一眼看懂，限定负责不让标题被读成
> "所有投资者最长只需要 340 天便能盈利"——窗口内仍有 49 个起点至今未达标，
> 它们由四个补充数字里的"尚未达标"如实披露。
> 更早的标题"定投 +5%：已达标样本中的最长等待期"里嵌着 340 这个**数据值**，
> 改一次数据就要改一次文案，而且它长得像一句结论而不是一个问题。

右栏**没有行数硬上限**，但也不许失控：上限（40）由 `home.test.ts` 守着，
而真正的问题是"一组里的指标能不能互相解释"——那一组要么回答同一个问题，
要么彼此不相关到可以分开。白名单住在 `packages/metrics/src/home.ts`，
由 `home.test.ts` 逐个点名守住（不许在页面层写死 id 列表）。
注册表里的其余指标**一个都不删**——它们仍然有详情页，仍然参与规则计算。

**当前状态列表达的是市场含义，不是数据质量。** 两个都叫"状态"，容易混：

- 这一列回答"**这个数相对它自己近一年处在什么位置**"——中性 / 净流入 / 拥堵 / 缺数据。
- 数据质量是另一回事，只在异常时以小标记挂在**数值后面**（待更新 / 暂无数据 / 文件异常 / 历史不足）。

把它们合成一列的后果是：读者开始把"抓取失败"和"市场很冷"读成同一种灰，
而这两个词对读者意味着完全相反的事。

判定依据列（`xl` 起显示）说清这个词怎么来的：`近1年 P66`、`7日净流入 1,173 BTC`。
它一律**由数据生成**（`statusBasis`），不逐指标写死文案——
写死的解释迟早和数值对不上。算不出来时它显示**短原因**（`历史不足` / `数据不足`），
而不是把内部 metric id 与长错误信息摆到首页上；
完整解释留在 `title`（悬停可见）与指标详情页。

**这一格必须单行。** 它是表格里的一列，不是一段话：
"指标 pool-concentration 的历史不足 365 天，无法做分位标准化"会把行高撑成两行，
把整张表的下沿顶开。短版 + `whitespace-nowrap` 双保险；
但 `nowrap` 只是保险，文案本身必须先短下来。

右栏是**真表格**（`<table>` + `rowSpan`），不是 div 拼出来的"看起来像合并单元格"。
分类合并是**语义**（同一个分类跨了这些行），读屏软件会把它读成"分类：市场"；
div 拼出来的假合并只能被读成十九个互不相干的词。

分类单元格在整段合并区里**水平 + 垂直居中**，用真正的单元格对齐
（`text-center align-middle`），不用绝对定位模拟。

**只有指标名称本身可点。** 第一版不做整行可点。
上一版的"拉伸链接"（`<Link>` 上的 `after:absolute after:inset-0` + `<tr>` 上的 `relative`）
在真实浏览器里是场灾难：绝对定位的后代在表格行里的包含块并不可靠，
伪元素会盖住整张表甚至整页——于是**点页面任意位置都跳到最后一个指标**
（矿工收入）的详情页，连页头的品牌字标都被它吃掉。
表格可点的收益很小，"点哪都跳走"的代价极大，所以点击面积收回指标名本身。

窄屏下长数字会折行：数值列用 `wrap-anywhere`（`overflow-wrap: anywhere`），
它把单元格的最小内容宽度降到 1 个字符，表格因此能收进视口；
`break-words` 不够——它不改变最小宽度，于是
"$1,524,281,584,722.37" 这类数字会把整张表撑到 381px，在 375px 屏上溢出 26px。
`sm` 以上恢复默认，桌面端长数字仍完整显示在一行里。

窄屏（<1024px）降级为上下堆叠：顶部长指标 + 走势图 + 下方分组表格，**允许纵向滚动**。
并排两栏在窄屏上等于把每一栏都压到读不了。

**窄屏收起两列**：分类列（`<lg` 隐藏，改由组标题承担分组边界）与
判定依据列（`<xl` 隐藏）。表头必须跟着列一起收——表头数量与列数对不上时，
读屏软件会把第 3 个表头念到第 2 列上。
组标题用 `scope="colgroup"`，分类单元格用 `scope="rowgroup"`。

## 6. 移动端与键盘

### 6.1 320px 不溢出

首页表格在窄屏**收起一列**而不是加横向滚动条：分类列收起，
分组边界由组标题承担（标题本来就要给读屏软件用，视觉上顺便把组分开了）。

数值列是 `w-28`（112px）、变化列 `w-16`（64px），`sm` 起才放宽。
市值 `$1,646,907,492,049.81` 有 21 个字符，等宽 14px 下约 176px——
超出数值列的宽度，靠 `overflow-wrap: break-word` 折行，**不撑破布局**。

详情页的指标数值同理：`text-2xl` 起、`sm` 才升到 `text-3xl`，并允许 `break-words`。

`body` 上有 `overflow-wrap: break-word`：中文没有词间空格，
长 endpoint（`https://blockstream.info/api/block/0000…`）必须能断行，
源码 URL 一律配 `break-all`。

### 6.2 键盘可达性

- **`:focus-visible`** 才有焦点环，2px `var(--ink)` + 2px offset。
  鼠标点击不出现，键盘 Tab 一定看得见——深色主题下浏览器默认焦点环常常和背景撞色。
- **跳过导航链接**（`.skip-link`）：首页 19 行都是链接，键盘用户每翻一页都要 Tab 过。
  平时用 `position: absolute; left: -9999px` 移出视口，**不用 `display: none`**
  （那样它就无法被聚焦，跳过链接会彻底失效）；聚焦时回到文档流。落点是 `<main id="content">`。
- 语义标签：该用 `<article>` / `<section>` / `<dl>` 的地方都用上了
  （`Freshness` 是 `<dl>`，图表是 `<figure>` + `role="img"` + `aria-label` 描述显示区间）。
- `prefers-reduced-motion: reduce` 时关掉全部动画与过渡。

第 10 条守的是一个**完全静默**的 bug：`next/font` 的变量原来挂在 `<body>` 上。
Tailwind 把 `--font-sans: var(--font-inter), …` 声明在 `:root`（即 `<html>`），
而 CSS 自定义属性的 `var()` **在声明处替换**——那一刻 `<html>` 上还没有 `--font-inter`，
`--font-sans` 直接变成 guaranteed-invalid，且这个 invalid 状态会**原样继承**给所有后代，
**不会**在 `<body>` 上重新求值。结果是构建产物 CSS 一字不差地正确，
但页面上一个 web font 都没加载，退回系统字体也**没有任何报错**。

这些测试读的是**源码文本**而非渲染结果——本站构建期静态生成，
除 `browser.test.ts` 之外没有浏览器运行时可挂。
代价是管不了"class 用对了但位置对不对"，只管"用词是否越界"。
`browser.test.ts` 补上这一层：有浏览器与预览服务时它是真的点。

## 8. 明确不做的事

| 不做 | 为什么 |
|---|---|
| 涨跌染色 | 方向因指标而异，染色等于替读者下判断（§1.1） |
| 用底色表达好坏 | 底色只做分组，不表态（§1.4） |
| 手动主题切换开关 | 需要首帧前的内联脚本，而闪烁本就不存在（§3） |
| 卡片墙 / 阴影 / 渐变 / 胶囊圆角 | 视觉红线（§1.2） |
| 首页迷你走势图 | **已推翻**（ADR-017 之后）：首页放十年价格走势图，绿段只标最长等待区间 |
| 恒显的数据质量"正常"列 | 一列永远写着"正常"的信息等于没有信息；只在异常/过期/历史不足时挂标记 |
| 给颜色赋予涨跌或好坏含义 | 方向因指标而异，染色等于替读者下判断（§1.1、§1.4、ADR-017） |
| 状态色用绿色 | 绿色已经是"最长等待期"，绿色也表示"偏强"的话"绿色 = 好"就长回来了（§1.6） |
| "超买 / 超卖"这类振荡器词 | 本站没有 RSI，MVRV 之外也没有振荡器。借一个读者已内建好的结论，\
而那个结论并不来自我们的计算（§1.6、`status-specs.ts`） |
| 为了表格整齐而填"中性" | "中性"是有立场的结论，"判不了"不是（§数据质量红线 8） |
| 交互式图表库 | 静态快照用不上 50 KB 客户端 JS（ADR-009） |
| 图表 tooltip / 缩放 | 同上；若日后要做，接受"加一层轻交互"的重做成本 |
| 打包等宽字体 | 元信息全是数字与短标签，系统等宽足够（§2.3） |
